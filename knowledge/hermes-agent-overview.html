01

Apa itu Hermes Agent Gateway?

Hermes Agent Gateway adalah platform middleware agentic AI enterprise yang dikembangkan untuk menghubungkan sistem internal PT EKSAD (aplikasi web, backend service, atau alat pengembang) dengan Large Language Models (LLM) tingkat tinggi seperti MiniMax-M2, Claude Sonnet 4, dan GPT-4o.

Berbeda dengan panggilan API LLM konvensional yang hanya melakukan tanya-jawab teks biasa, Hermes Gateway berfungsi sebagai Agen Cerdas Berbasis Profile (Profile-Driven Agent) yang dibekali konteks arsitektur, instruksi sistem (SOUL.md), serta sekumpulan skill/tools otomatis.

🧩 Multi-Profile Architecture

Mendukung pemisahan tugas agen secara terisolasi pada port terpisah. Contoh: Profile system-analyst berjalan di port 8643 khusus membuat TSD & DDL, sedangkan profile business-analyst berjalan di port 8642 untuk BRD/FSD.

🛠️ Native Skills & Tools Integration

Agen mampu menjalankan perkakas teknis seperti eksad-tsd-design, eksad-adr-workflow, dan eksad-appsec-review untuk menghasilkan dokumen teknis standar enterprise secara konsisten.

💾 Persistent Session Management

Menyediakan database SQLite internal di level profile untuk mencatat dan mengingat seluruh riwayat obrolan (Chat History) per sesi/tiket secara permanen.

⚡ Smart Context Compressor

Secara otomatis memadatkan obrolan lama (*summarization & sliding window*) jika jumlah token percakapan mendekati batas maksimum context window LLM.

02

Gimana Cara Komunikasinya?

Komunikasi dengan Hermes Agent Gateway dilakukan menggunakan protokol HTTP/HTTPS REST API dengan format pertukaran data JSON Payload. Akses diamankan menggunakan Bearer Token Authentication (API_SERVER_KEY).

🔒 Header Autentikasi Wajib: 
Authorization: Bearer 10ff9bb178374d9e1d23d1c39abcd305d3566820151b2edfd72e939290e58fe9

Dua Moda Komunikasi Utama:

1. Moda Stateless (OpenAI Compatible Protocol `/v1`)

Client mengirimkan array messages lengkap dari awal hingga akhir pada setiap request. Gateway tidak menyimpan riwayat obrolan ke database sesi. Moda ini sangat cocok untuk integrasi aplikasi yang sudah mengelola history sendiri di sistem internal.

2. Moda Stateful (Native Hermes Sessions `/api/sessions`)

Client menginisialisasi sesi terlebih dahulu untuk mendapatkan session_id. Obrolan berikutnya cukup mengirimkan pesan baru, dan Hermes secara otomatis memuat history terdahulu dari database SQLite, memprosesnya, dan menyimpan respon terbaru ke sesi yang sama.

Alur Eksekusi Internal Gateway (Lifecycle):

1
Inbound Request & Authentication

Gateway menerima HTTP Request pada port profile (misal 8643), memvalidasi Bearer Token API_SERVER_KEY.

2
Session Context Binding

Jika memanggil `/api/sessions`, gateway memanggil _bind_api_server_session() untuk memuat riwayat obrolan & variabel user_context dari SQLite DB (response_store.db).

3
Agent Execution & Tool Invocation

Agen menjalankan instruksi sistem (*SOUL.md*), memanggil tool jika diperlukan (misal generator TSD/DDL), dan mengirim prompt ke LLM underlying.

4
Context Compression & Persistence

Jika token mendekati limit, context_compressor memadatkan obrolan lama. Respon akhir dan token accounting (`input_tokens`, `output_tokens`) disimpan kembali ke SQLite DB.

03

Apa Saja Endpointnya?

Berikut adalah katalog lengkap endpoint HTTP REST API yang disediakan oleh Hermes Agent Gateway:

Method Endpoint Path Protokol Deskripsi Fungsi
GET /v1/models OpenAI Health check & melihat informasi model aktif pada profile server.
POST /v1/chat/completions OpenAI Kirim pesan obrolan dalam format stateless standar OpenAI.
GET /api/sessions Native Melihat daftar seluruh sesi obrolan yang tersimpan di server.
POST /api/sessions Native Membuat sesi percakapan baru (mengembalikan `session_id`).
POST /api/sessions/{session_id}/chat Native Kirim obrolan lanjutan ke sesi tertentu (disimpan otomatis).
GET /api/sessions/{session_id}/messages Native Tarik seluruh riwayat percakapan (Chat History) dari sesi.
DELETE /api/sessions/{session_id} Native Hapus sesi obrolan tertentu dari database server.
