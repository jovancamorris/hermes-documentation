Cakupan & Peran Agen System Analyst

Profile system-analyst bertugas merancang arsitektur sistem teknis yang konsisten dengan standar EKSAD:

  • TSD (Technical Specification Document) — Penulisan dokumen spesifikasi teknis lengkap.
  • Data Model & Flyway DDL — Desain skema database SQL migration sesuai konvensi EKSAD (7 audit columns: tenant_id, created_at, created_by, updated_at, updated_by, deleted_at, deleted_by).
  • API Contract Design — Katalog endpoint REST API, proteksi RBAC @RolesAllowed, dan struktur request/response JSON.
  • RabbitMQ Event Schemas — Desain event envelope untuk komunikasi asinkron antar microservice (exc-{domain}). *Catatan: Digunakan kondisional bila service membutuhkan event-driven architecture / async audit logging. Jika service murni Synchronous REST API, RabbitMQ dapat dilewati.
  • Sequence & AppSec STRIDE Modeling — Diagram alur request-response dan pemetaan ancaman keamanan STRIDE.

Daftar Request dalam Postman Collection, Fungsi, & Skenario Penggunaannya:

Folder Nama Request Method Endpoint & Parameter Fungsi & Kegunaan Utama Skenario Penggunaan (Real-World)
OpenAI Compatible (/v1) 1. Health Check - List Models GET /v1/models Memeriksa kesehatan server gateway SA (Port 8643) & memastikan model system-analyst aktif. Verification check ketersediaan gateway SA sebelum eksekusi otomatis generator TSD/DDL script atau integrasi backend.
2. Chat Completion (Stateless) POST /v1/chat/completions
Body: messages[]		 Mengirim prompt skenario SA tanpa simpan sesi (stateless). Respon teknis langsung dikembalikan tanpa menyimpan riwayat database. Pembuatan draf cepat snippet DDL Flyway tunggal, struktur RabbitMQ Event Envelope, atau validasi konvensi nama kolom SQL.
Native Sessions (/api/sessions) 1. Create New Session POST /api/sessions
Body: {"title": "..."}		 Starter chat yang disimpan di SQLite/PostgreSQL server (auto-capture session_id ke Postman variable). Inisialisasi perancangan TSD/proyek microservice baru (contoh: "svc-user-management") untuk memelihara konteks arsitektur teknis.
2. Send Chat to Session (Stateful) POST /api/sessions/:session_id/chat
Body: {"message": "..."}		 Mengirim instruksi arsitektur teknis lanjutan secara interaktif berkesinambungan dengan konteks teknis yang dipelihara di database server. Perancangan TSD multi-tahap (misal: "Buat DDL PostgreSQL" ➡️ "Tambahkan audit trail" ➡️ "Buatkan RabbitMQ Event Schema").
3. Get Session Messages History & Usage GET /api/sessions/:session_id/messages Mengambil seluruh rekam jejak riwayat perancangan TSD & akumulasi pemakaian token (accumulated_usage). Memuat ulang dokumentasi TSD pada UI SA, atau menguji konsistensi skema database yang dihasilkan agen selama proses perancangan.
4. Get All Active Sessions List GET /api/sessions Memanggil daftar seluruh sesi percakapan aktif yang tersimpan di database server. Menampilkan daftar sesi proyek TSD aktif di dashboard UI atau audit administrasi server.
5. Delete Session DELETE /api/sessions/:session_id Menghapus data sesi perancangan TSD beserta seluruh riwayatnya dari database server. Membersihkan sesi draft arsitektur yang dibatalkan atau menghapus memori perancangan setelah DDL/TSD berhasil di-commit ke Git.

Cara Import & Menggunakan di Postman:

  1. Download file JSON di atas atau copy isi skema JSON di bawah ini.
  2. Buka Postman ➡️ Klik tombol Import (kiri atas).
  3. Drag & Drop file JSON atau Paste teks skema.
  4. Variabel {{baseUrl}} (http://203.145.34.37:8643) dan {{apiKey}} sudah terkonfigurasi secara otomatis.
  5. Jalankan request 1. Health Check lalu coba Create New Session (variabel {{session_id}} terisi otomatis) & Send Chat to Session.
