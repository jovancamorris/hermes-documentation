Arsitektur Multi-Tier Storage & Memory Management Plugin ke Vector RAG

Panduan teknis mendalam mengenai arsitektur hirarki penyimpanan (*Storage Hierarchy*) Hermes Agent pada server `203.145.34.37` dan mekanisme integrasi **Plugin Long-Term Memory (LTM) ke Vector RAG Store** untuk *Cross-Session Knowledge Retrieval*.

1. Hirarki Penyimpanan & Tipe Storage Hermes Agent

EKSAD Hermes Agent menggunakan 4 Tipe Storage berhirarki yang bekerja secara komplementer berdasarkan masa pakai (*lifetime*) dan kegunaannya:

Level 1: RAM Volatile (STM)

Short-Term Memory / Context Window

  • Tempat: RAM Server (LLM Context Buffer).
  • Masa Pakai: Ephemeral (hilang saat prompt selesai / context shift).
  • Fungsi: Penampung pesan obrolan aktif secara real-time.
Level 2: Relational DB (LTM)

SQLite / PostgreSQL Server DB

  • Tempat: /opt/hermes/data/hermes.db / Server DB.
  • Masa Pakai: Permanent (Survives server restart & crash).
  • Fungsi: Menyimpan sessions, messages, user_context (8 vars), & token usage.
Level 3: Disk File System

Physical Disk Storage (SSD)

  • Tempat: /home/eksadpro/projects/... & docs/.
  • Masa Pakai: Permanent (Persisted on SSD disk).
  • Fungsi: Menyimpan bundel file fisik (TSD_*.md, V1__init_*.sql, README.md).
Level 4: Vector RAG Store

Vector DB & Embeddings Store

  • Tempat: Qdrant / PgVector / ChromaDB.
  • Masa Pakai: Permanent & Indexed.
  • Fungsi: Similarity search pengetahuan & ADR lintas sesi (Cross-session memory recall).

Matriks Penggunaan Tipe Storage Berdasarkan Kejadian (Timeline Execution)

Waktu / Event Penggunaan Tipe Storage yang Digunakan Operasi Teknis & Deskripsi Data
1. POST /api/sessions Level 2 (Relational DB) Membuat baris cangkang baru di tabel sessions dan menyimpan 8 variabel user_context.
2. POST /api/sessions/{id}/chat Level 1 (RAM) + Level 2 (DB) Mengambil riwayat obrolan dari DB ke RAM Context Window, lalu menyimpan baris pesan baru ke tabel messages.
3. Eksekusi Skill Generator (TSD/Flyway) Level 3 (Disk SSD) Menulis file bundel fisik (TSD_*.md, V1__init_*.sql) ke folder /home/eksadpro/projects/....
4. Auto-Indexing Knowledge to RAG Level 4 (Vector RAG) Plugin RAG mengekstrak poin keputusan penting dari TSD/ADR, me-vectorize, dan menyimpannya ke Vector Store.
5. Session Baru Bertanya Topik Sama Level 4 (Vector RAG) → Level 1 (RAM) Agen melakukan similarity search via RAG API dan menginjeksi konteks jawaban dari sesi lama ke RAM agen baru.

2. Arsitektur Plugin Hermes Memory Management ke Vector RAG

Bagaimana agen Hermes mengintegrasikan Stateful Session Memory ke Vector RAG Store agar pengetahuan dan keputusan arsitektur dapat di-recall oleh agen pada sesi berikutnya:

flowchart TD subgraph Client ["Client / Postman / Portal"] A["POST /api/sessions/:id/chat"] end subgraph HermesCore ["Hermes Agent Core Engine"] B["Stateful Session Memory (Level 2 DB)"] C["Memory Sync Plugin / Extractor"] end subgraph VectorRAG ["Vector RAG Infrastructure (Level 4)"] D["Text Chunking (512 tokens)"] E["LLM Embedding Model (text-embedding-3-small)"] F[("Vector DB (Qdrant / PgVector / Chroma)")] end subgraph CrossSession ["Future Agent Session"] G["New Session Query ('Apa keputusan arsitektur project Nagamas?')"] H["RAG Retrieval Skill (eksad-rag-retrieval-workflow)"] I["Semantic Similarity Search (top_k=5)"] J["Context Injection to Prompt Window"] end A -->|1. Store Message| B B -->|2. Trigger Memory Sync| C C -->|3. Extract Key Facts/ADR| D D -->|4. Generate Vector| E E -->|5. Store Embeddings & Metadata| F G -->|6. Query| H H -->|7. Vector Match| F F -->|8. Relevant Context| I I -->|9. Inject Context| J

Alur Kerja Integrasi Plugin Step-by-Step:

  1. Memory Extraction Event: Saat sesi percakapan menghasilkan deliverable penting (seperti TSD, ADR, atau Flyway Schema), Plugin Memory Hermes mengekstrak blok keputusan arsitektur.
  2. Chunking & Metadata Tagging: Teks dipecah menjadi chunk berukuran 512 token dan ditandai dengan metadata isolasi: user_id, project_id, tenant_id, dan doc_type.
  3. Vector Embedding Conversion: Plugin mengirimkan chunk ke model embedding (contoh: text-embedding-3-small) untuk menghasilkan vektor n-dimensi (1536 dimensi).
  4. Vector DB Indexing: Embeddings disimpan ke Vector Database (PgVector / Qdrant) pada server.
  5. Cross-Session Semantic Recall: Ketika pengguna membuat sesi baru pada proyek yang sama dan mengajukan pertanyaan terkait keputusan lama, skill eksad-rag-retrieval-workflow memanggil RAG API untuk menyuntikkan memori secara relevan tanpa perlu mengulang instruksi dari awal.

3. Konfigurasi Plugin & Skill Snippet (`eksad-rag-retrieval-workflow`)

Konfigurasi plugin memory management pada hermes-config.yaml dan contoh payload pemanggilan RAG Retrieval API:

Konfigurasi Plugin Memory Hermes Server (/opt/hermes/config/plugin-memory-rag.yaml):

# /opt/hermes/config/plugin-memory-rag.yaml
memory_plugin:
  enabled: true
  provider: "vector-rag-sync"
  storage_target: "pgvector"
  vector_db_url: "postgresql://hermes:secret@203.145.34.37:5432/hermes_vectors"
  embedding_model: "text-embedding-3-small"
  chunk_size: 512
  chunk_overlap: 64
  metadata_filters:
    - "user_id"
    - "project_id"
    - "tenant_id"
  auto_sync_on_deliverables:
    - "TSD_DESIGN"
    - "ADR_WORKFLOW"
    - "FLYWAY_DDL"
yaml
